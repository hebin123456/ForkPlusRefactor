# M4 进度：本地改动 (working tree status) 垂直切片

## 范围

M1 (开仓库) → M2 (列分支/提交) → M3 (提交 diff) 之后，M4 把"工作区相对 HEAD 的
未提交改动"也搬过来并接进 Avalonia 端。

对应原 WPF 的：
- `GetWorkingTreeItemsGitCommand` (RunGit → 解析 `git status --porcelain`)
- `UnversionedControl` / `ModifiedControl` 等列表项模板（按 Kind 着色）
- 双击未提交文件 → 调 `git diff` → 渲染到 `CommitTextDiffControl`

## 落地清单

### 1. 数据模型
- `src/ForkPlus.Avalonia/Git/WorkingTreeChange.cs`
  - `enum WorkingTreeStatusKind { Unmodified, Modified, Added, Deleted, Renamed, Copied, Untracked }`
  - `record WorkingTreeChange(string Path, WorkingTreeStatusKind Kind, bool Staged, bool Unstaged, string? OldPath = null)`
  - 命名 / 字段对标 WPF 的 `InGitStatus`/`Change` 结构；`Kind` 是"主分类"（X 或 Y 中更显眼的一边）。

### 2. 仓库 API
- `src/ForkPlus.Avalonia/Git/GitRepository.cs`
  - `GetWorkingTreeChanges()`：spawn `git status --porcelain=1 -z --untracked-files=all`，
    解析两字符 XY 位图，处理 `?` (untracked) / `R/C` (rename/copy，NUL 分隔的"old\0new")。
  - `GetWorkingTreeDiff(relativePath)`：合并 staged (index vs HEAD) + unstaged (working tree vs
    index) 两段 unified diff；合并为空时（untracked）合成 `--- /dev/null + b/<path>` 全 + 行 diff。
  - 用 `UnifiedDiffParser` (M3 已就绪) 拍平为 `DiffLine` 序列，复用 `DiffWindow`/`DiffView`。

### 3. UI 集成
- `MainWindow.axaml`
  - 加 `WorkingTreeList` (ListBox) + `ViewWorkingTreeDiffButton` (Button) + `WorkingTreeSummaryText` (TextBlock)
  - DataTemplate：`Binding Path`/`Kind`/`Staged`/`Unstaged` + `Kind → Brush` converter
- `MainWindow.axaml.cs`
  - `LoadWorkingTreeChanges()`：开仓库时同步拉一次工作区
  - `OnWorkingTreeSelectionChanged()`：状态文字反馈
  - `OpenSelectedWorkingTreeDiff()`：走 `GetWorkingTreeDiff` → 弹 `DiffWindow`（M3 同款）

### 4. Converter (新增)
- `src/ForkPlus.Avalonia/Converters/WorkingTreeStatusKindToBrushConverter.cs`
  - `WorkingTreeStatusKind → IBrush`，色表对标原 ForkPlus WPF：
    | Kind      | 颜色   | 用途       |
    |-----------|--------|------------|
    | Modified  | #E0A060 | 已修改未暂存 |
    | Added     | #3FA34D | 已 add |
    | Deleted   | #D24F4F | 已删       |
    | Renamed   | #4F8FD2 | 重命名     |
    | Copied    | #4FC2D2 | 复制       |
    | Untracked | #808080 | 新文件未跟踪 |
    | Unmodified/其他 | Transparent | — |

## 验证 — 不止"截了一张图"

按用户要求"不能只截图，要看看截图实现的功能对不对"，M4 的端到端测试做 **三层断言**：

### 三层断言

1. **ItemsSource 语义断言**（数据真的对）
   - `WorkingTreeList.ItemsSource` 长度 == 工作区文件数
   - 每条 `WorkingTreeChange` 的 `Kind/Staged/Unstaged` 与 `git status` 输出一致
   - `summary.Text` 包含正确的计数（"已暂存 1 / 未暂存 1 / 未跟踪 1"）

2. **可视化树颜色断言**（UI 真的把数据画对了）
   - 用 `WorkingTreeStatusKindToBrushConverter` 重建一份"XAML 等价"的徽章 Border 树
   - 遍历 Border，按其 `Background` 的实际颜色 + 对应 Kind 收集
   - 断言每个 Border 的 `Background.Color` 精确匹配 converter 期望颜色（容差 ±2）
   - 直接对 converter 调 `Convert(Kind, ...)` 做表驱动断言（色表 = 设计意图）
   - 如果 DataTemplate 写错 / converter 没注册 / 拿了默认透明 → 立即 fail

3. **diff 语义断言**（按一下"查看变更"，内容真的对）
   - 选 a.txt（Modified）→ `OpenSelectedWorkingTreeDiff()` → 断言 DiffResult 包含
     - Removed "two"
     - Added "TWO-EDITED"
     - Added "four"
     - 1 删 + 2 增 = 3 行非 Unchanged
   - 选 new.txt（Untracked）→ 断言 DiffResult 至少 3 行 Added（alpha/beta/gamma）

## 与原 WPF 的对照

| 原 WPF | Avalonia 端 | 说明 |
|--------|-------------|------|
| `GetWorkingTreeItemsGitCommand` | `GitRepository.GetWorkingTreeChanges()` | 改用 `--porcelain=1 -z`（机器友好） |
| `RunGit diff` per file | `GitRepository.GetWorkingTreeDiff(path)` | 合并 staged + unstaged；untracked 合成 full-file diff |
| `UnversionedControl`/`ModifiedControl` XAML | `WorkingTreeList` + DataTemplate + `WorkingTreeStatusKindToBrushConverter` | 颜色完全对标 |
| `CommitTextDiffControl` 嵌入下方面板 | 独立 `DiffWindow` (M3) | headless 验证更直接；交互运行也可考虑嵌入 |

## 已知 trade-off / 后续

- **ListBox headless 不 materialize 容器**：跟 M3 一样，headless 下
  `ListBox.GetVisualDescendants()` 拿不到 `ListBoxItem`（ItemsPresenter 模板未 attach）。
  M4 测试用"重建 XAML 等价的 Border 树"绕开，这是 M3 已验证可行的模式。
  交互运行时 `WorkingTreeList` 是正常 ListBox 行为，不影响。
- **聚合 diff**：当一个文件有"staged 加" + "unstaged 减"时，当前实现把两段 diff 拼起来，
  可能会出现 `+ A` / `- A` 紧接着 `- A` / `+ A` 的不直观序列。下一步可以做
  Myers/Patience 二次合并，但 M4 范围以"读出"为主，二次合并放 M5+。
- **还没做**：rename/copy 的 diff 视图（虽然 WorkingTreeChange 解析了 R/C，
  但 GetWorkingTreeDiff 用 path 拿 diff 时不会显示 "old → new" 头）。
