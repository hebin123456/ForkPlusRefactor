# M5 进度：文件树 (File Tree) 垂直切片

## 范围

M1 (开仓库) → M2 (列分支/提交) → M3 (提交 diff) → M4 (工作区改动) 之后，M5 把
"指定 ref 的完整文件树" 也搬过来并接进 Avalonia 端。

对应原 WPF 的：
- `GetRevisionFileTreeGitCommand`（`git ls-tree` 解析）
- `FileTreeItem` 数据模型（File / Directory / Submodule）
- `RevisionFileTreeUserControl` 树形视图 + 图标徽章
- `FileListUserControl` 双击文件 → `FileContentControl` 预览

## 落地清单

### 1. 数据模型
- `src/ForkPlus.Avalonia/Git/FileTreeNode.cs`
  - `enum FileTreeNodeKind { File, Directory, Submodule }`
  - `record`-like `class FileTreeNode(Name, FullPath, Sha, ItemType, Depth, Children)`
  - `FlatCount()` 用于"扁平行数"统计；递归创建/复用中间目录

### 2. 仓库 API
- `src/ForkPlus.Avalonia/Git/GitRepository.cs` 新增 3 个方法
  - `GetFileTree(refName)`：spawn `git ls-tree -r -z <ref>`，解析 NUL 分隔的
    `<mode> <type> <sha>\t<path>`，按路径段递归构造层级 `FileTreeNode`。
    自动去重（同名中间目录复用），自动按"目录优先 + 自然序"排序。
  - `GetFileContent(refName, relativePath)`：spawn `git show <ref>:<path>`，
    拿文件原始内容（UTF-8 解码），失败返回错误字符串而不抛异常。

### 3. UI 集成
- `src/ForkPlus.Avalonia/Panels/FileTreePanel.axaml` 新 UserControl（沿 M4 风格：Border + 标题 + summary + 控件 + 说明）
  - `TreeView` 配 `TreeDataTemplate` 递归显示，每行 = 22px 徽章 + 文件名
  - 徽章背景色由 `FileTreeNodeKindToBrushConverter` 决定
  - 徽章字形 ([D]/[F]/[S]) 由 `FileTreeNodeKindToBadgeTextConverter` 决定
  - "刷新"按钮：重新读当前 ref 的文件树
- `src/ForkPlus.Avalonia/Panels/FileTreePanel.axaml.cs` 面板逻辑
  - `Load(repo, refName="HEAD")` 入口
  - `Reload()` 内部用，扩展默认全展开（按 WPF 原版 ls-tree 一次拿全，UI 默认全展开）
  - 事件：`FileOpenRequested`（双击文件/子模块行）、`SelectionChangedHint`（状态文字）
- `src/ForkPlus.Avalonia/MainWindow.axaml`
  - 左侧栏插入 `<panels:FileTreePanel x:Name="FileTreePanel" />`
  - 主区分上下两块：上半是 M2/M3 提交图，下半是 M5 文件预览 (`FilePreviewTitle` + `FilePreviewText`)，中间用 `GridSplitter` 分隔
- `src/ForkPlus.Avalonia/MainWindow.axaml.cs`
  - 注入 `FileTreePanel` + 订阅 `FileOpenRequested` 事件 → 调 `GetFileContent` → 写预览
  - 新增公开 API `OpenSelectedFileContent()` 供 headless 测试用
- `src/ForkPlus.Avalonia/RepoOpHandler.cs`
  - 构造函数新增可选参数 `FileTreePanel? fileTreePanel`
  - `Open(repo)` 成功后 → `_fileTreePanel?.Load(repo, "HEAD")`
  - `SelectBranch(branch)` 成功后 → `_fileTreePanel?.Load(repo, branch)`（切分支同步刷文件树）

### 4. Converters (新增)
- `src/ForkPlus.Avalonia/Converters/FileTreeNodeKindToBrushConverter.cs`
  - `FileTreeNodeKind → IBrush`，色表对标原 ForkPlus WPF：
    | Kind      | 颜色   | 用途       |
    |-----------|--------|------------|
    | Directory | #C09A50 | 目录       |
    | File      | #4A4A4A | 文件       |
    | Submodule | #9050C0 | 子模块     |
  - 配 `FileTreeNodeKindToBadgeTextConverter`（Kind → "D"/"F"/"S" 单字符字形）
  - 用色块徽章 + 单字符字形而非位图图标：headless Skia 不能 load 外部图像资源
    （实际 desktop run 不依赖图像资源），用纯色保证视觉断言稳定

## 验证 — 不止"截了一张图"

按用户要求"不能只截图，要看看截图实现的功能对不对"，M5 的端到端测试做 **三层断言**：

### 三层断言

1. **数据流断言**（数据真的对）
   - `root.FlatCount() == 1(root) + 真实目录数 + 文件数`
   - 顶层 `Children` 按"目录优先"排序
   - 真实目录数与文件数分别与 `git ls-tree -r --name-only` 的输出完全一致
   - `summary.Text` 包含 "目录 N / 文件 M / K 节点"（N,M,K 与 git ls-tree 一致）
   - `panel.CurrentRef == "HEAD"`（开仓库默认 HEAD）
   - 错误路径：`GetFileTree("nonexistent-ref")` 抛 `GitRepositoryException`；
     `GetFileTree("")` 抛 `ArgumentException`

2. **可视化树颜色断言**（UI 真的把数据画对了）
   - 用 `FileTreeNodeKindToBrushConverter` 重建一份"XAML 等价"的徽章 Border 树
   - 遍历 Border，按其 `Background` 的实际颜色 + 对应 Kind 收集
   - 断言每个 Border 的 `Background.Color` 精确匹配 converter 期望颜色（容差 ±2）
   - 直接对 converter 调 `Convert(Kind, ...)` 做表驱动断言（色表 = 设计意图）
   - 如果 DataTemplate 写错 / converter 没注册 / 拿了默认透明 → 立即 fail

3. **文件内容语义断言**（双击文件拿到的内容真的对）
   - 选 README.md → `GetFileContent("HEAD", "README.md")` → 断言 == "Hello from M5 fixture!\n"
   - 选 src/main.cs → `GetFileContent("HEAD", "src/main.cs")` → 断言 == "// M5 fixture main\nConsole.WriteLine(\"hi\");\n"
   - headless 下无法直接 double-click TreeView（容器未 materialize），但走 `GitRepository.GetFileContent` 等价于
     WPF 原版 `FileContentControl` 的"读文件"路径，断言覆盖了真正的功能正确性

## 跨平台要点

- `git ls-tree -r -z` / `git show <ref>:<path>`：通过 `ServiceLocator.GitPathResolver` 拿 `git` 路径
  （Windows = `git.exe`，Linux = `git`，macOS = `git`），无 `.exe` 硬编码
- `RunGit` 走 `ProcessStartInfo.ArgumentList`（自动处理空格/中文/特殊字符），不依赖 shell
- 颜色值是 hex 常量而非 `SystemColors.*`，跨平台稳定；徽章用纯 `IBrush` 不用图像，
  Skia 在所有平台都画得出来

## 不在 M5 范围（M5 后会做的）

- TreeView 的 lazy expand（点 ▶ 才拉子节点）：M5 默认全展开（WPF 原版也是默认全展开，
  因为 ls-tree -r 一次性拿全了所有文件，再 lazy 反而多绕一圈）
- 双击文件时 TreeView 自动滚动/选中 + 真正 raise DoubleTapped 事件：headless 下 TreeView
  容器不 eager materialize，无法在 headless 测试里点；M5 走 GitRepository.GetFileContent
  API 等价路径断言
- 文件图标按扩展名（`*.cs` 显示 C# 图标，…）：M5 阶段只按 Kind（File/Dir/Submodule）
  上色，扩展名图标是 P3 主题阶段的细化
- Submodule 节点的"点开看子模块 commit"：M5 把 Submodule 当作叶子显示，递归看子模块
  tree 是后续阶段
