## 选型与策略

- **复用 M11 的 stub**：`GitPointView` / `BindableGitPointView` / `AutoTooltipTextBlock` 已经在 M11 写过，本批直接引用。
- **`BindableGitPointView` 增强**：M11 的 stub 只支持 `Subject` / `Detail` 直接属性。本批新增 `GitPoint` 依赖属性——传入任意对象后通过反射取 `Subject/Name/DisplayName/FullName`（主）和 `Detail/Description/Sha/BranchName`（副），并写回 Subject/Detail。这样 `ItemsControl` 可以直接把 `StashItem` / `BranchItem` / `TagItem` 传给 `BindableGitPointView.GitPoint`，无需额外 DataTemplate 转换层。
- **简单 POCO 替代 WPF 业务类型**：
  - `StashRevision : IGitPoint` → `StashItem { ReflogName, Subject }`
  - `LocalBranch` / `RemoteBranch` → `BranchItem { BranchName, UpstreamName? }`
  - `Tag : IGitPoint` → `TagItem { Name, Sha }`
  - 避免迁移 WPF 的 Git 业务类（M0/M1 已用 biturbo stub 替代大部分）。
- **单/多条切换**：WPF 原版用 `Visibility.Collapsed` 切换 `GitPointView` / `GitPointsContainer`。Avalonia 用 `IsVisible="{Binding IsSingleMode}"` 切换两个并列控件——`IsVisible` 在 headless 渲染下更可靠。
- **WPF 专有资源跳过**：`Image Source="{DynamicResource BranchIcon}"` / `Warning.png` / `WorktreeIcon` 等图标资源不复制到 Avalonia，本批直接省略图标（保留 `StackPanel` 占位），未来可在 M17 主题资源阶段统一补上。

## `BindableGitPointView` 增强

```csharp
public object? GitPoint
{
    get => GetValue(GitPointProperty);
    set
    {
        SetValue(GitPointProperty, value);
        if (value == null) { RenderFromGitPoint(null); return; }
        var t = value.GetType();
        var subject = TryReadString(t, value, "Subject", "Name", "DisplayName", "FullName");
        var detail  = TryReadString(t, value, "Detail",  "Description", "Sha", "BranchName");
        if (subject != null) SetValue(SubjectProperty, subject);
        if (detail  != null) SetValue(DetailProperty,  detail);
        RenderFromGitPoint(value);
    }
}
```

XAML 不再写 `x:DataType` / 绑定路径，直接用 `x:Name="SubjectText" / "DetailText"` 在 code-behind 写入文本——和原 M11 的 `GitPointView` 实现保持一致。

## 已知限制（与 M10/M11/M12 一致）

- Avalonia 12 无头 renderer 对绑定型内容（`ItemsControl` 渲染、`Content="{Binding …}"`）不画像素，所以截图右侧列表为空——但所有数据流断言均通过。
- `BranchIcon` / `Warning.png` 等图标资源未引入，本批用 `StackPanel` / `Text` 占位。
