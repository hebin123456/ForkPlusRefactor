# M7 进度：标签 (Tag) 垂直切片

## 目标

把 WPF 原版 `TagList` 侧栏（含 annotated / lightweight 区分、查看 commit、删除本地 tag）从 245 个 XAML 中抽出，
以"先垂直切片"方式迁到 Avalonia 跨平台版 MainWindow 左侧栏。

M7 是 M1-M6 之后的下一个自然切片：和 M6 一样，都是 git 仓库对象的"只读列表 + 简单操作"，只是数据源
从 `git stash list` 换成 `git for-each-ref refs/tags/`。

## 实现范围

- [x] 数据模型 `GitTag`（不可变 record：Name / Sha / PeeledSha / IsAnnotated / Tagger / TagDate / ShortSha / DisplayLine）
- [x] 仓库 API：`GitRepository.GetTags()` + `GitRepository.DeleteLocalTag(name)`
- [x] 视觉标记：两条 Converter
  - `GitTagKindToBrushConverter`：`bool IsAnnotated` → 棕色 `#A05F2A`（annotated）/ 灰色 `#6E6E6E`（lightweight）
  - `GitTagKindToBadgeTextConverter`：`bool IsAnnotated` → 单字符 `"a"` / `"l"`
- [x] `TagsPanel` UserControl（ListBox + View / Delete 按钮 + 状态摘要）
- [x] 接入 `MainWindow` 左侧栏（位于 M6 stash 面板下方、M4 工作区上方）
- [x] `RepoOpHandler` 同步加载：开新仓库时 `TagsPanel.Load(repo)` 自动跑一次
- [x] 事件处理：MainWindow 接 `ViewRequested` → 选 branch 拉 commits；`DeleteRequested` → `DeleteLocalTag` + reload

## 三层断言（与 M4/M5/M6 一致）

### 1) 数据流断言
- 准备 4 个 commit → 创建 4 个 tag（2 annotated + 2 lightweight），混合 target commit SHA
- `GitRepository.GetTags()` 拿 4 条 → 断言：
  - 顺序 = 字典序（`v0.1.0`, `v0.2.0`, `v1.0.0`, `v1.1.0`）
  - `Name` / `PeeledSha` / `IsAnnotated` 跟 `git for-each-ref --format=...` 原文逐条对比
  - annotated 走 `*objectname`（peeled）路径，lightweight `*objectname` 为空回退到 `objectname`
  - summary 文案 = "共 4 条 tag（2 个 annotated，2 个 lightweight），按字典序。"
  - ListBox.ItemCount == 4
  - DisplayLine 形态：annotated `[a] xxx (yyy)` / lightweight `[l] xxx (yyy)`

### 2) 可视化徽章颜色断言
- 重建 XAML 等价 `StackPanel`：每行 = `Border(Background=KindToBrush)` + 字形 "a"/"l" + 名称 + sha
- 遍历 `Border.Background` 颜色：
  - 第 0 条（v0.1.0）= `#6E6E6E`（lightweight 灰）✓
  - 第 1 条（v0.2.0）= `#A05F2A`（annotated 棕）✓
  - 第 2 条（v1.0.0）= `#A05F2A`（annotated 棕）✓
  - 第 3 条（v1.1.0）= `#6E6E6E`（lightweight 灰）✓
- 容差 ±2

### 3) 操作语义断言
- `DeleteLocalTag("v0.1.0")` → `GetTags()` 从 4 变 3，reflog 已无 v0.1.0
- `DeleteLocalTag("v0.1.0")` 再删一次（已不存在）→ 抛 `GitRepositoryException`
- `DeleteLocalTag("")` / `"   "` → 抛 `ArgumentException`
- `Load(null)` → `Repository == null` + `ItemsSource == null` + 摘要 = "未打开仓库。"

## 跨平台实现要点

- **不用 biturbo 的 `bt_get_tags`**：M6 阶段调研时 `BtTagDetails` / `BtRepositoryStashes` 等结构体已就位，但
  P/Invoke ABI 在 Linux 上还没 smoke 测过。M7 走 `git for-each-ref --format=...` CLI 路径更稳，且和
  M4/M5/M6 完全一致（统一"git CLI 优先，biturbo 兜底"的策略）。
- **6 段 ASCII Unit Separator (`\u001f`)** 分隔字段：tag name 允许含 `/`，tagger 含空格 / 尖括号，
  常规的 `|` 容易和 tagger 内部冲突；用 `\u001f` 保证字段解析不歧义。
- **lightweight tag 的 `*objectname` 字段为空**：直接回退到 `objectname`（target commit 本身），
  后续 `ShortSha` / `PeeledSha` 都统一指向 commit，对 UI 一致。
- **Cross-platform screenshot**：headless 模式下中文字符显示成方块（缺中文字体），但 layout /
  颜色 / 几何对比与 WPF 原版完全一致；这是预期行为，所有 M2-M6 截屏也都遵循同一约束。
