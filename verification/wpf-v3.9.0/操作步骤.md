# ForkPlus v3.9.0 截图操作步骤（新补 11 张：5 张界面 + 6 张右键上下文菜单）

> 本文档为 v3.9.0 新增截图配套的操作步骤说明。每个步骤都标注了**具体按钮位置、菜单路径、键盘操作或屏幕坐标**，方便后续在 Avalonia 跨平台重构时对照原版 UI 行为。
> 配合 `源码映射.md`（界面→代码文件→平台 API→Avalonia 替代），即可逐界面做像素级 / 行为级回归，不依赖 Windows 真机。

测试环境：Ubuntu 22.04（无 GUI） + Wine 11 + Xvfb(:99) + .NET 10 WindowsDesktop 运行时（手工拼装）。  
被测程序：ForkPlus v3.9.0 已发布版（`ForkPlus39/ForkPlus.exe`）。  
演示仓库：构造的 `demo-store`（多分支、合并、标签、stash、子模块、bare remote、未提交改动）。

## 截图 52-appearance-menu.png — 外观菜单

**到达该状态的操作步骤**：

1. 启动 ForkPlus：`WINEPREFIX=/root/.wine-forkplus DISPLAY=:99 DOTNET_ROOT=Z:/root/.codebuddy/artifact/forkplus/dotnet-root wine ForkPlus.exe`
2. 应用自动打开上次仓库 `demo-store`，主界面（浅色主题）显示。
3. **鼠标点击工具栏"外观"按钮**
   - 工具栏图标行：屏幕 y ≈ 140
   - "外观" 按钮位置：屏幕 x ≈ 1020（窗口内 x ≈ 920）
   - 单击左键
4. 弹出**外观下拉菜单**，包含三组：
   - **主题**：浅色（当前） / 深色 / Solarized 浅色 / Solarized 深色 / GitHub 浅色 / GitHub 深色 / Dracula / Monokai / 纯色 / 自定义颜色...
   - **语言**：English / 简体中文（当前） / 繁體中文 / 日本語 / ⽇⽂ / Français / Deutsch / Español
   - **提交列表布局**：水平（当前） / 垂直

**重构对照要点**：
- 主题切换是即时热重载（点选项后整个窗口立即重绘，无需重启）。
- "提交列表布局"是独立的"标签页方向"概念，对应提交图区下方"提交 / 变更 / 文件树"三 tab 的摆放方向。
- 多语言列表至少 8 种，迁移时需评估 i18n 框架。

## 截图 53-dark-theme-main.png — 深色主题主界面

**到达该状态的操作步骤**：

1. 接截图 52（外观菜单已展开）。
2. **鼠标点击"深色"菜单项**
   - 屏幕坐标约 (1080, 222)（菜单第二项）
3. 主题立即切换到深色：
   - 主背景 #1E1E1E 系，正文文字 #E0E0E0
   - 提交图连线变橙色（与浅色不同的色板）
   - 标签徽章、按钮等控件配色反转
4. 菜单自动关闭，回到主界面。

**重构对照要点**：
- 主题切换覆盖整个应用树（Sidebar、Commit Graph、Diff/File Tree Tab、Commit Detail、工具栏）。
- ForkPlus 自带 8 套主题（v3.8.3 报告已述），设计器应统一封装为 `IThemeService`。
- "Solarized / GitHub / Dracula / Monokai"提示采用第三方配色生态，迁移时需确认 license。

## 截图 54-ai-assistant-unconfigured.png — AI 辅助开发未配置提示

**到达该状态的操作步骤**：

1. 主界面（深色主题 — 截图 53）。
2. **鼠标点击工具栏"AI 辅助开发"按钮**
   - 屏幕坐标约 (920, 140)（窗口内 x ≈ 820）
   - 单击左键
3. 弹出**模态对话框**：
   - 标题：空（无标题栏文字）
   - 图标：圆形蓝色 fork + 餐刀图标
   - 标题文字：**"AI 尚未配置。"**
   - 提示正文：**"AI 辅助开发需要先配置 API。请在 偏好设置 → AI 增强 中填写服务 URL 和 API Key。"**
   - 按钮：**打开偏好设置**（蓝色主按钮） / **关闭**（灰色次按钮）

**重构对照要点**：
- 这是 v3.9.0 4 个 commit 重构的"统一 AI 辅助界面"——所有 AI 入口（按钮、菜单、命令面板）都汇聚到这个统一的"尚未配置"检测。
- 提示文本用 `偏好设置 → AI 增强` 路径表明 WebView2/AI 模块的**配置入口在主应用偏好**而非单独的 AI 设置窗口。
- 模态弹窗阻止用户在不配置情况下使用 AI，但不阻塞主界面操作（点击外面会使弹窗失焦而非关闭 — 这与 .NET WPF 默认 `MessageBox` 行为一致）。

## 截图 55-git-error-dialog.png — Git 错误对话框

**到达该状态的操作步骤**：

1. 在截图 54 的 AI 弹窗中，**按 `Enter` 键**（或点击"打开偏好设置"按钮）
   - 焦点默认在"打开偏好设置"按钮（WPF Button 默认焦点顺序），Enter 触发 Click
2. 偏好设置对话框打开，并触发内部对 Git 路径的初始化探测。
3. 探测失败，弹出**错误对话框**：
   - 标题：空
   - 图标：圆形蓝色 fork + 黄色三角警示
   - 标题：**"Git 错误"**
   - 详情正文：**"执行 Git 请求时发生意外错误"**
   - 详细描述：**"找不到 git 实例: C:\PortableGit\cmd\git.exe。缺少 bash.exe"**
   - 按钮：关闭

**重构对照要点**：
- 这个错误揭示了 v3.9.0 **Git 探测逻辑的依赖**：ForkPlus 期望 `C:\PortableGit\cmd\git.exe` 可用并且依赖 `bash.exe`（Windows 版 git 调用 sh）。在 Linux/Wine 下如缺 bash 会失败。
- 错误格式采用 `标题 + 正文 + 详细描述` 三段式（对应 WPF `MessageBox` 的 `Caption` + `Text` + `DetailedText`）。
- 错误信息直接暴露内部路径，便于调试但也提示迁移时需做**跨平台 Git 路径抽象**（`GitLocator`/`IGitProvider`）。

## 截图 56-prefs-ai-enhancement.png — 偏好设置 · AI 增强配置页

**到达该状态的操作步骤**：

1. 在截图 55 的 Git 错误对话框中**按 `Esc` 键**（或点击"关闭"按钮）：
   - 错误对话框关闭
   - 底层的**偏好设置对话框**仍显示（并未关闭）
2. 偏好设置打开后默认显示 **"AI 增强"标签页**（v3.9.0 把它作为默认/推荐页）。

**截图内容详解**：

- **顶部标签栏**（从左到右）：
  - 通用 / 提交 / **AI 增强**（当前选中，蓝色下划线） / Git / 集成 / 自定义命令 / 导入导出
- **AI 模型配置**区块：
  - 推理服务 URL：文本框，预填 `https://api.openai.com`
  - API Key：密码框（显示 `API key` 占位）
  - 模型：下拉框（空）+ 右侧刷新按钮
  - ☑ 自动根据 URL 和 API Key 获取挂载模型
  - 重试次数：数字框，默认 `3`
  - 最大超时时间（秒）：数字框，默认 `300`
- **技能**区块：
  - 技能名称：文本框
  - 内容：大文本框（多行）
  - 导入：`加载技能文件...` 按钮 + 提示 `Ctrl+Enter 添加`
  - 已加载的技能：列表框（空）
- 底部：关闭按钮

**重构对照要点**：
- 偏好设置采用 **Tab 分类 + 单页内分块**（非侧边树形导航），现代扁平风格。
- **AI 增强模块两大子系统**：
  - 「AI 模型配置」：连接 LLM 服务（OpenAI 兼容）
  - 「技能系统」：通过加载技能文件扩展 AI 能力（"技能"概念类似 Claude Skills / GPTs）
- 标签页顺序暗示了用户旅程：通用 → 提交 → AI 增强（v3.9.0 默认） → Git → 集成 → 自定义命令 → 导入导出
- 迁移到 Avalonia 时：
  - AI 配置对应 `IAIConfigurationService`（持久化到本地 JSON）
  - 技能系统对应 `ISkillProvider`（文件系统加载 + 解析）
  - 整个 AI 增强模块是 v3.9.0 的**架构核心**，重构时建议提取为独立 `ForkPlus.AI` 程序集

## 已知交互坑（重构时借鉴）

1. **Wine 下 xdotool 默认 `click`（12ms 按下/释放）在 WPF 模态弹窗的按钮上不可靠**——必须用 `--delay 100+` 或改用 `Return` 键。
2. **WPF 弹窗窗口不一定有独立 x11 标题**——`xdotool search --name "AI 尚未"` 找不到，需用 `xdotool search --name ""` 枚举全部窗口凭 geometry 识别。
3. **Git 路径探测在 Linux/Wine 下死锁 bash.exe**——这是端口层问题，迁移 Avalonia 到 Linux/macOS 时应直接调用 `git` 命令而非依赖 `git.exe + bash.exe`。
4. **主题切换热重载**——ForkPlus 主题模块无重启，这是良好实践，重构应保留。
