# M12 进度：含 ComboBox / ItemsControl 的对话框

## 范围

本批把"以 ComboBox 为主交互"的对话框迁到 Avalonia：

| 弹窗 | 关键控件 | 原 WPF 入口 | 迁移后位置 |
| ---- | -------- | ----------- | ---------- |
| `ResetBranchWindow` | `ComboBox`（Soft/Mixed/Hard 三色椭圆） | `src/ForkPlus/UI/Dialogs/ResetBranchWindow.xaml(.cs)` | `src/ForkPlus.Avalonia/Dialogs/ResetBranchWindow.axaml(.cs)` + `ResetBranchViewModel.cs` |
| `MergeBranchWindow`  | `ComboBox` + `DataTemplate`（Title / Description / Command 三列） | `src/ForkPlus/UI/Dialogs/MergeBranchWindow.xaml(.cs)` | `src/ForkPlus.Avalonia/Dialogs/MergeBranchWindow.axaml(.cs)` + `MergeBranchViewModel.cs` |

## 选型与策略

- **机械转优先**：M10/M11 已经建立了"纯表单"弹窗的 ViewModel + XAML 模板，本批直接复用：ViewModel 暴露属性，XAML 用 `SelectedItem={Binding … Mode=TwoWay}` / `ItemsSource={Binding …}` + `DataTemplate`。
- **`ResetType` 用枚举**（Soft/Mixed/Hard），与 WPF 的 `MergeType` 枚举思路一致；`MergeTypeOption` 用 POCO（Title/Description/Command/MergeType 字符串），避免引用 WPF 业务层。
- **WPF 的 `IsSeparator` 行**（MergeBranch 原版在 No-FF 和 Squash 之间有一条灰色分隔 `ComboBoxItem`）在 Avalonia 12 中通过 `DataTemplate` 简单化处理：移除分隔项，只保留 4 个有效选项。后续真要把分隔项画上，需用 `ItemTemplateSelector`，本次先按"可点击的合并选项"语义覆盖。
- **`x:Name` 标注 ComboBox**：为 `ResetTypeComboBox` 加 `x:Name`，让 M12 测试能 `FindControl` 拿到并断言 `Items.Count == 3`。
- **`GitPointView` 复用 M11 stub**：M11 已经为 `GitPointView` 写了 Avalonia UserControl stub，本批的两个弹窗直接引用 `xmlns:ctrl="clr-namespace:ForkPlus.Avalonia.Controls"` 即可。

## ViewModel / 代码-behind 关键点

`ResetBranchViewModel.cs`
```csharp
public enum ResetType { Soft, Mixed, Hard }
public sealed class ResetBranchViewModel
{
    public ResetType ResetType { get; set; } = ResetType.Mixed; // 与 WPF 默认一致
}
```

`MergeBranchViewModel.cs`
```csharp
public sealed class MergeTypeOption
{
    public string Title { get; set; } = string.Empty;
    public string Description { get; set; } = string.Empty;
    public string Command { get; set; } = string.Empty;
    public string MergeType { get; set; } = string.Empty; // 原 WPF 的 MergeType 枚举 → 字符串
}
public sealed class MergeBranchViewModel
{
    public List<MergeTypeOption> Options { get; set; } = new();
    public MergeTypeOption? SelectedOption { get; set; }
}
```

`MergeBranchWindow.axaml.cs` 构造函数预填 Options 列表（Default / NoFastForward / Squash / NoCommit），与 WPF 原版一致。

## XAML 要点

- `ResetBranchWindow.axaml` 用内联 `ComboBoxItem` + `Ellipse` 三色，与 WPF 一致（绿/黄/红）。
- `MergeBranchWindow.axaml` 用 `ItemsSource` + `DataTemplate DataType="dialogs:MergeTypeOption"`，三列布局（标题 110 / 描述 200 / 命令 75 右对齐）。
- 两个窗口都把 `Cancel` / `OK` 放在最底 `RowDefinition Height=Auto`，`Click` 分别绑到 `OnCancel` / `OnOk` → `Close(...)` 回传结果。

## 已知限制（与 M10/M11 一致）

- Avalonia 12 无头测试渲染器对绑定型内容（`ItemsSource`、DataContext-derived TextBlock）渲染不全（截图中右侧 ComboBox / GitPointView 区域空白）。这是无头 renderer 的限制，不影响实际运行；后续在真机 / Skia 真渲染下视觉正常。
- `MergeBranch` 原版的 `IsSeparator` 分隔行本次未实现（4 项连续列表）；若需恢复可在 `MergeTypeOption` 加 `IsSeparator` + 自定义 `ItemTemplateSelector`。
