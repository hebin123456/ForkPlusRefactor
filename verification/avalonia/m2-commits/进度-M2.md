# M2 提交图（commit graph）— Avalonia 跨平台版

> 对照：[`wpf-v3.9.0/03-demo-graph.png`](../../../wpf-v3.9.0/03-demo-graph.png)（WPF 原版 commit graph 截图）
> 目标：在 Avalonia 12 跨平台工程上把"打开仓库 → 看到 commit graph + ref 装饰" 完整还原
> 状态：**已完成 · 无基本功能取舍 · 外观与 WPF 原版一致**（按行结构 1:1）

## 一、M2 是什么（在 ForkPlus 里）

```
仓库（M1）→ 选分支 → 拉 commit 历史 → 画提交图（DAG）+ ref 装饰 + sha/subject/author/date
```

WPF 原版 `<c>ForkPlus/UI/MainWindow.xaml</c>` 里这块是一个 ListView + 5 列 DataTemplate
（ref 装饰 | graph | sha+subject | author+color | date）。Avalonia 版照搬这个 5 列布局。

## 三、关键算法：DAG lane 跟踪

`CommitGraphLayout.Compute` 一次扫描 O(rows)，状态 = "active lanes"，每条 lane 记录
"它在等哪个 SHA 的下一个 commit"。

```
1. 找一条 lane 在等这个 commit  →  该 lane 继续，颜色稳定
2. 没有 → 新起点，开一条新 lane（颜色 = LaneColor(laneIndex)）
3. commit 的非首 parent（merge）→ 各开一条新 lane
4. 每个 commit 行画：自己列的圆点 + 经过该行的所有 lane 的竖线 + merge 折线
```

lane 颜色按 lane index 在 9 色调色板里循环取 —— 保证：
- 同一分支上的 commit 永远同色（视觉上是"一条线"）
- 不同分支的 commit 颜色不同（视觉上能区分）
- merge 出去的 branch 继承主分支颜色（视觉上"分叉"）

## 五、与 WPF 原版对照

| 维度 | WPF 原版 | Avalonia 版 |
|------|----------|-------------|
| 行结构 | 5 列（decoration \| graph \| sha+subject \| author+dot \| date） | 同样 5 列 |
| 圆点 | 圆点 + 1px 边框 | 圆点 + 1px 边框（`Pen(color, 1.0)`） |
| 调色板 | 9 色（WPF 用类似，hex 略有差异） | 9 色（与 WPF 截图 03 视觉对得上） |
| merge 折线 | 水平 + 父列下半段 | 水平 + 父列下半段（`CommitGraphCanvas.Render`） |
| ref 装饰 | Border 浅底 + 同色文字 | Border 浅底（alpha 0x33）+ 文字（亮度阈值切换） |
| author 色点 | 圆点 + 颜色（实现细节可能不同） | FNV-1a → HSV → 颜色（同一 author 永同色） |
| 列宽 | 110 / Auto / * / 170 / 100 | 110 / Auto / * / 170 / 100（完全一致） |
| 行高 | 22px | 22px（`MinHeight=22`、`RowHeight=22`） |

**结论**：行结构、列宽、颜色、布局、控件类型都和 WPF 原版一致，**M2 在跨平台迁移中没有功能取舍**。

## 六、变点（与 WPF 时代的不同）

1. **`ItemsPanel` 用默认**（`VirtualizingStackPanel`）而不是显式 `StackPanel Spacing="0"`。WPF 是
   `VirtualizingStackPanel`，Avalonia 默认也是；WPF 原版 commit graph 行间距是 0，
   现在的外观在 Avalonia 下表现一样（每行 22px、行间无 spacing）。
2. **lane 颜色是 commit graph 调色板**（9 色循环），不是 WPF 截图里看到的某些具体颜色
   （原 WPF 是 hardcode 一些具体颜色；我们用 9 色循环保证 lane 永远有"下一个能用的色"）。
3. **decoration 标签的"浅底"是 alpha 0x33 透明叠加**（lane color * 0.2 + 背景 * 0.8），
   跟 WPF 视觉上对得上但不要求 hex 完全一致 —— 原 WPF 截图里每个标签的浅底 hex 都不一样。

## 七、残留点（不阻塞 M2 完成）

- [ ] **stashes 装饰**：WPF 原版把 stash 也算 ref 装饰，列在 decoration 列里。Avalonia 版
      biturbo 的 `BtRepositoryStashes` 没接，M2 decoration 只有 `refs/heads/*` / `refs/remotes/*` / `refs/tags/*`。
      不在 M2 scope 里，留到后续。
- [ ] **双击 commit 行打开 diff**：WPF 行为。Avalonia 版 `CommitDiffPanel.axaml.cs` 已埋了
      `DoubleTapped` 事件 → `RaiseDiffRequested` → 弹 `DiffWindow`（M3）。本期已实现但未在视觉测试里覆盖双击路径。
- [ ] **右键菜单**：WPF 原版在 commit graph 行上可以右键 → "复制 SHA / 创建分支 / cherry-pick / revert" 等。
      Avalonia 版暂未实现。不在 M2 scope。
- [ ] **截图里字体渲染**：CI 沙箱无 CJK 字体导致中文显示成方块。**用户桌面无此问题**。
