# ForkPlus v3.9.0 功能验证报告（Ubuntu / Wine 环境）

> 验证时间：2026-08-09 · 环境：Ubuntu 22.04 沙箱（无图形界面）+ Wine 11 + Xvfb + 手工拼装的 .NET 10 WindowsDesktop 运行时

## 1. 结论：原版客户端可在纯 Linux 环境完整运行

**ForkPlus v3.9.0 的 Windows 发行版已在纯 Linux 沙箱中成功启动并跑通完整 Git 工作流**，覆盖启动、打开仓库、提交图浏览、Diff/文件树、各类右键上下文菜单、本地改动暂存、提交 / Pull / Push、Undo / Redo、新建分支 / 标签、子模块、Open With、控制台、Work 下拉等。共 **62 张截图**（含 6 张右键上下文菜单），见同目录 `verification/v3.9.0/`（或本目录下的 `index.html` 索引）。另有配套的 `源码映射.md` 提供界面→代码→平台 API→Avalonia 替代的精确映射。

这为本工程迁移到 Avalonia 提供了「随时可启动、可截图、可自动化对比」的**标准答案基准**——不需要 Windows 真机也能逐页做像素级 / 行为级回归。

## 4. 原版程序的两处崩溃点（已用 IL 补丁绕过）

原版 `ForkPlus.dll` 在 Wine 下有两处必崩，均为 **Wine 未实现的 WinRT API**（真 Windows 上完全正常），v3.9.0 中依然存在：

| # | 崩溃点 | 原因 | 补丁方式 |
|---|--------|------|---------|
| 1 | `SystemThemeHelper.SubscribeToSystemEvents()` | `UISettings.ColorValuesChanged` 事件订阅在 Wine 返回 E_NOTIMPL | 方法体替换为 `ret` |
| 2 | `SystemThemeHelper.GetSystemBrush()` | 依赖 UISettings 取系统强调色，返回空引用 | 方法体替换为返回 `null`（上层有 fallback 画笔） |

补丁工具：Mono.Cecil（`patcher.cs`），只跳过系统主题感知，应用自带主题不受影响（深色主题切换已验证）。

## 7. 对 Avalonia 迁移的对照价值

1. **基准对照通道已打通**：Wine 环境可随时启动原版截图，v3.9.0 已覆盖 62 个界面 / 交互点，迁移过程中每个页面都能拿到标准答案做对比，不依赖 Windows 真机。
2. **交互可自动化验证**：xdotool 能驱动原版走完整流程，迁移后用 `Avalonia.Headless` 做同样操作，行为级回归可行。
3. **风险集中在三点**（与 v3.8.3 结论一致，且 v3.9.0 让 AI 界面区域更聚焦）：
   - **WebView2 替换**：v3.9.0 统一了 AI 流式界面，是迁移重点，需选 `WebView.Avalonia` / `CefGlue` 方案；
   - **Toast / 系统主题的平台抽象**：Wine 下已验证仅两处 WinRT 调用需平台适配；
   - **XAML 逐页翻译**：WPF→Avalonia 是 XAML 技术栈里迁移成本最低的路径，AI 界面统一后结构更清晰。
4. **其余基本是平移**：Rust 引擎（`biturbo.dll`）、`tokei.exe` 代码统计、git 子进程调用、MVVM 业务层，跨平台无压力。

## 8. 源码级重构对照手册（`源码映射.md`）

与本文档（视觉/行为基准）配套，另有一份 **`源码映射.md`**，基于 v3.9.0 真实源码（`src/`，1862 文件）静态审计生成，提供比截图更深一层的逻辑对照：

- **架构接缝**：`ServiceLocator` 已抽象 7 个平台接口（`IDispatcher`/`IClipboardService`/`IToastNotificationService`/`IWindowManagerService`/`IAppContext`/`IDesignModeService`/`ITimerService`），各有一个 `Wpf*` 实现——Avalonia 端只需补 `Avalonia*` 实现。
- **平台依赖清单**：按替换成本排序，含 WebView2/AI 渲染、AvalonEdit、OxyPlot.Wpf、UISettings+注册表主题检测、WindowsCredentialManager、Shell 集成、Git 路径硬编码（git.exe/bash.exe）等，并给出 Avalonia 替代方案。
- **界面→代码文件映射**：主界面、140+ 对话框、7 个偏好标签页、AI 系列窗口、账户登录等，精确到 `.xaml/.cs` 文件。
- **重构路线图**：6 阶段（骨架→核心视图→对话框→AI 渲染→平台服务→验证回归）。
- **最大利好**：Git 引擎 `biturbo` 已发布 Windows/Linux/macOS 三平台原生库，核心 Git 逻辑无需重写。

> 使用方式：截图告诉"界面长什么样、点了什么"；`源码映射.md` 告诉"这段代码在哪、平台依赖是什么、Avalonia 端怎么替换"。三者（截图 + 操作步骤 + 源码映射）配合做逐界面回归。

## 9. 本轮补拍环境限制与未覆盖项
