## 原版程序的两处崩溃点（已用 IL 补丁绕过）

原版 `ForkPlus.dll` 在 Wine 下有两处必崩，均为 **Wine 未实现的 WinRT API**（真 Windows 上完全正常）：

| # | 崩溃点 | 原因 | 补丁方式 |
|---|--------|------|---------|
| 1 | `SystemThemeHelper.SubscribeToSystemEvents()` | `UISettings.ColorValuesChanged` 事件订阅在 Wine 返回 E_NOTIMPL | 方法体替换为 `ret` |
| 2 | `SystemThemeHelper.GetSystemBrush()` | 依赖 UISettings 取系统强调色，返回空引用 | 方法体替换为返回 `null`（上层有 fallback 画笔） |

补丁工具：Mono.Cecil（`patcher.cs`），只跳过系统主题感知，应用自带 12 套主题不受影响（深色主题切换已验证）。

## 完整的 Windows 依赖清单（迁移到 Avalonia 的真实工作量）

对 `ForkPlus.dll` 做了全量 IL 反编译扫描，**WinRT 使用面非常小**：

| 依赖 | 用途 | Avalonia 迁移建议 |
|------|------|------------------|
| `Windows.UI.ViewManagement.UISettings` | 系统主题/强调色感知 | 平台抽象接口；Linux 读 freedesktop 设置，macOS 读 NSAppearance |
| `Windows.UI.Notifications.ToastNotification*` | Toast 通知 | 平台抽象；Linux 用 libnotify，macOS 用 UNUserNotificationCenter |
| `WebView2` | AI 流式 Markdown 渲染 | **最大替换点**：Avalonia 需选 WebView.Avalonia / CefGlue 方案 |
| `biturbo.dll`（Rust 原生） | 底层引擎 | 无压力：Rust 直接编 `.so`/`.dylib`，P/Invoke 声明不用改 |
| `tokei.exe` | 代码统计 | 无压力：cargo 跨平台编译 |
| WPF 字体/DirectWrite 文本栈 | 文本渲染 | 无需处理：Avalonia 用 Skia 自绘，跨平台一致性反而更好 |
| git 子进程调用 | 全部 Git 操作 | 无压力：git 全平台都有 |

**UI 层（XAML）**：主工程约 3.8 万行 IL，XAML 界面数十个窗口/控件（CustomWindow、AI 系列界面、提交图、热力图、树图等），这是迁移的主要工作量，但 WPF→Avalonia 是 XAML 技术栈里迁移成本最低的路径。

## 对 Avalonia 迁移的直接价值

1. **基准对照通道已打通**：这套 Wine 环境可以随时启动原版客户端截图，迁移过程中每个页面都能拿到"标准答案"做像素级对比，不依赖 Windows 真机。
2. **交互行为可自动化验证**：xdotool 可以驱动原版做完整操作流程（打开仓库→看 diff→切主题），迁移后用 Avalonia.Headless 做同样操作，行为级回归可行。
3. **风险集中在三点**：WebView2 替换、Toast/系统主题的平台抽象、XAML 逐页翻译。其余（Rust 引擎、git 集成、MVVM 业务层）基本是平移。
