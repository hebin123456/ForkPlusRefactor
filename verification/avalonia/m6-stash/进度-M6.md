# M6 进度：贮藏 (Stash) 垂直切片

## 范围

M1 (开仓库) → M2 (列分支/提交) → M3 (提交 diff) → M4 (工作区改动) → M5 (文件树) 之后，
M6 把 "git stash list + apply/pop/drop/show diff" 也搬过来并接进 Avalonia 端。

对应原 WPF 的：
- `GetStashesGitCommand`（`git stash list` 解析）
- `StashListUserControl` 侧栏列表 + 上下文菜单（apply / pop / drop / show）
- `StashApplyGitCommand` / `StashPopGitCommand` / `StashDropGitCommand` 操作链

## 落地清单

### 1. 数据模型
- `src/ForkPlus.Avalonia/Git/GitStash.cs`
  - `record`-like `class GitStash(ReflogIndex, ReflogSelector, Sha, Branch, Message)`
  - `DisplayLine`：UI 侧栏单行展示（"branch: message"）
  - 关键不变量：`ReflogSelector`（`stash@{0}`）是 apply/pop/drop 的 key，**不要用 Sha**（pop 之后该 SHA 不在 reflog 里了）

### 2. 仓库 API
- `src/ForkPlus.Avalonia/Git/GitRepository.cs` 新增 5 个方法
  - `GetStashes()`：spawn `git stash list --format=%gd|%H|%s`，按行解析
    - `%gd` = reflog selector（`stash@{N}`）
    - `%H` = stash commit 完整 SHA
    - `%s` = subject（`On &lt;branch&gt;: &lt;msg&gt;`）
  - `StashPush(message)`：spawn `git stash push --include-untracked [-m msg]`
  - `StashApply(selector)`：spawn `git stash apply &lt;selector&gt;`
  - `StashPop(selector)`：spawn `git stash pop &lt;selector&gt;`
  - `StashDrop(selector)`：spawn `git stash drop &lt;selector&gt;`
  - `GetStashDiff(selector)`：spawn `git stash show -p --no-color &lt;selector&gt;` → UnifiedDiffParser
  - 跨平台说明：biturbo 已暴露 `bt_get_repository_stashes` + `BtStash` 结构体，
    但 P/Invoke ABI 在 Linux 上没 smoke 测过；CLI 路径简单稳定，后续若 biturbo 跑通可切换

### 3. UI 集成
- `src/ForkPlus.Avalonia/Panels/StashPanel.axaml` 新 UserControl（沿 M4/M5 风格）
  - 标题 + summary + ListBox（180px 高）+ Apply/Pop 按钮 + Drop/ShowDiff 按钮
  - 每行 = [蓝色 `stash@{N}` 徽章（#3A5F8A）] + DisplayLine + SHA 摘要
  - 徽章用纯 `IBrush`（Skia 跨平台稳定）而非位图
- `src/ForkPlus.Avalonia/Panels/StashPanel.axaml.cs` 面板逻辑
  - `Load(repo)` / `Reload()`：拉 stash 列表
  - 事件：`ApplyRequested` / `PopRequested` / `DropRequested` / `ShowDiffRequested`（用户点按钮 / 双击行）
  - `SelectionChangedHint`：选行时把 `stash@{N} - sha7 - branch: msg` 写到主窗口状态栏
- `src/ForkPlus.Avalonia/MainWindow.axaml`
  - 左侧栏插入 `<panels:StashPanel x:Name="StashPanel" />`（在 M5 文件树和 M4 工作区之间）
- `src/ForkPlus.Avalonia/MainWindow.axaml.cs`
  - 注入 `StashPanel` + 订阅 4 个事件
  - `OnStashApplyRequested` → `StashApply` + reload 本面板 + reload M4 工作区
  - `OnStashPopRequested` → `StashPop` + reload（栈少 1 条 + working tree 变）
  - `OnStashDropRequested` → `StashDrop` + reload（栈少 1 条，working tree 不变）
  - `OnStashShowDiffRequested` → `GetStashDiff` + 弹 `DiffWindow`（M3 复用）
- `src/ForkPlus.Avalonia/RepoOpHandler.cs`
  - 构造函数新增可选参数 `StashPanel? stashPanel`
  - `Open(repo)` 成功后 → `_stashPanel?.Load(repo)`

## 验证 — 不止"截了一张图"

按用户要求"不能只截图，要看看截图实现的功能对不对"，M6 的端到端测试做 **三层断言**：

### 三层断言

1. **数据流断言**（数据真的对）
   - `git stash list --format=...` 原文行数 == `GetStashes().Length`（=3）
   - 顺序：最新在前 → `stash@{0}` = "util.cs 第一次改"，`stash@{1}` = "main.cs 也改了"，`stash@{2}` = "README 改了"
   - 每个 `Sha` 必须匹配 `^[0-9a-f]{40}$`
   - `summary.Text` 包含 "共 3 条 stash"
   - 错误路径：`StashApply("")` / `StashPop("")` / `StashDrop("")` 抛 `ArgumentException`；
     `StashApply("stash@{99}")` 抛 `GitRepositoryException`（ref 不存在）

2. **可视化徽章颜色断言**（UI 真的把数据画对了）
   - 用 StashPanel.axaml 的真实配色（#3A5F8A）重建"XAML 等价"StackPanel
   - 遍历 Border，断言每个徽章 `Background.Color` 精确匹配（容差 ±2）
   - 找到 N 个徽章 Border 且 N >= stash 条目数

3. **操作语义断言**（apply / pop / drop 真的改了仓库状态）
   - `Apply stash@{1}`：working tree 的 `main.cs` 变成 stash 里的 `// M6 changed main\n`；stash 栈仍是 3 条
   - `Pop stash@{0}`：working tree 的 `util.cs` 变成 `// M6 changed util\n`；stash 栈从 3 变 2
   - `Drop stash@{0}`：working tree 不变；stash 栈从 2 变 1
   - `GetStashDiff("stash@{0}")` 拿到的 unified diff 的 +/- 行数 == `git stash show -p` 原文 +/-
   - 把最后一条 drop 完，`GetStashes()` 返回空数组

## 跨平台要点

- `git stash` 子命令在 Win/Linux/macOS 都可用，无需特殊适配
- `git stash list --format=%gd|%H|%s` 是 git 2.6+ 标准 format 占位符（`%gd` = reflog selector）
  - Win: 旧 PowerShell 调用 git 可能因 shell 转义出问题；用 `ProcessStartInfo.ArgumentList` 直传规避
  - Linux/macOS: `Process` + `ArgumentList` 直接用，无 shell
- 颜色值是 hex 常量（#3A5F8A）而非 `SystemColors.*`，跨平台稳定
- 徽章用纯 `IBrush` 不用图像，Skia 在所有平台都画得出来
